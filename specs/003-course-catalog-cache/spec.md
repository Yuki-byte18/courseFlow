# 课程目录本地缓存

本次选取第 4 项 FreeCache 和第 3 项缓存穿透、击穿、雪崩防护。两项共用课程管理页已有的查询 `GET /api/v1/courses?keyword=...`，沿用现有权限、响应格式和 MySQL 表结构。部署只需更新 Go API。

## 读取和失效规则

| 场景 | 行为 |
| --- | --- |
| 搜课程号、课程名或打开全部课程 | 每个 API 进程使用 32 MiB 的 FreeCache 数据缓冲区。缓存键包含课程目录版本、规范化后的条数上限和原始关键词摘要。 |
| 缓存穿透 | 查无结果时缓存空列表 5 至 9 秒，同一关键词再次查询可直接返回空数组。首次出现的不同关键词仍会查询 MySQL。数据库错误直接返回，后续请求可以重试。 |
| 缓存击穿 | 相同键并发未命中时，通过 singleflight 合并为一次查询。开始查库前再读一次缓存。每个请求可以独立取消等待，共享查询最多执行 5 秒。 |
| 缓存雪崩 | 有结果的条目独立随机缓存 60 至 90 秒，空结果也使用随机过期时间，将一批条目的到期时间分散。实例冷启动仍需回源。 |
| 管理员创建或编辑课程 | 数据库写成功后，当前进程立即递增目录版本。新请求跳过所有旧搜索结果，包括空列表。即使写入前启动的旧查询随后完成，也只能回填旧版本。 |
| 大结果或多实例 | 超过 FreeCache 单条大小限制时，本次正常返回，后续可再次回源。其他实例或直接写库的变更依靠各自条目的 TTL 可见。 |

缓存只存课程主数据。班次余量、学生身份、选课和退课继续沿用各自的实时查询与事务。

## 验收

从项目根目录进入 `backend` 后执行：

```sh
go test -race -v ./internal/course -run TestCatalog
go test ./...
go build ./...
```

测试使用计数回源函数和 Go 虚拟时钟，可以检查空结果和非空结果的过期窗口、同键并发的回源次数、取消等待、数据库错误重试，以及更新与旧查询同时发生的情况。

在管理端可用同一个关键词搜索两次，再创建一门匹配该词的课程并刷新。编辑课程名称后，按新旧名称分别搜索，即可检查当前实例上的目录更新。

## 本次验证结果

| 验证场景 | 观察结果 |
| --- | --- |
| 单元测试并发发起 32 次相同查询，取消首个请求 | 回源函数执行 1 次，其余 31 个请求均成功取得课程。 |
| 在独立的 MySQL 8.4.13 测试库中，通过管理员 HTTP 接口连续搜索两次 | 对无匹配关键词和有匹配关键词分别测试，MySQL 查询日志各记录到 1 次课程列表查询。 |
| 先搜索 Algebra 得到空列表，再创建 Algebra 课程并立即搜索 | 立即返回新课程。预先搜索 Geometry 并将课程改名为 Geometry 后，新词返回课程，旧词返回空列表。 |
